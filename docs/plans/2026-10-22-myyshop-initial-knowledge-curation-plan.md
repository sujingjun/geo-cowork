沿用现有知识条目清单，将 PR、官方社媒发文、官方网站页面整理为一版**有来源、有适用条件、可按批次确认的初始知识库**。

## 3. 三类素材的整理范围

### 3.1 PR 与相关媒体落地内容

1. 原样保留两份表格，登记文件校验值、工作表、单元格和超链接；正文提取不修改原件。
2. 全量登记链接，区分内容页、搜索结果页、跟踪跳转和重复链接。跟踪链接保留原值，同时解析最终目标；不以搜索结果页替代稿件正文。
3. 对 N3 先取得原发布正文，再按原稿、发布时间、内容相似性和来源署名识别同稿转载。每组以原发布和有实质差异的版本作为正文读取重点，其他回链保留分发关系与“未读取正文”标记。
4. 对 IMH 的 16 个落地链接逐一核对 MyyShop 相关段落。老文植入保留前后语境；文章原发布时间、更新日期和植入时间分别记录，未知时间不猜测。
5. 将材料中的终稿链接作为待读取来源，区分业务终稿与线上实际版本。二者不一致时记录差异；访问缺口仅影响对应材料。
6. 提取品牌定义、产品能力、规则条件、里程碑、案例和数字。新闻稿中的市场观点、效果宣称、媒体流量和宣发“影响力”保留原始口径，不能直接成为产品效果或实际阅读量。

本轮目标是取得不同内容及其来源关系，不逐页重复抓取同一篇稿件的全部转载，也不扩大为全网声誉调查。

### 3.2 官方社媒

整理对象限定为用户指定的 Instagram 与 TikTok 官方账号。普通评论、达人转发和合作方内容如被用作线索，单独标明作者与关系，不归入官方陈述。

建议首轮范围为账号简介、当前置顶内容，以及执行时冻结的最近 30 天公开发文；已有历史素材和与具体产品上线、规则变化相关的已知历史帖单独纳入，不受补缺窗口排除。登记准确起止时刻、时区和可见范围；不把有限窗口写成账号全历史覆盖。

每条保留帖子链接、账号、发布时间、正文、图片文字、可取得的字幕、产品链接和活动条件。图片识别文本需对应原图；未提供字幕或正文的音视频部分列为未读取，不从封面、标题或播放量推测视频内容，不为本次整理新建音视频采集系统。

遇到登录墙或读取不完整，优先使用业务提供的帖子链接清单、导出、截图与已有文案。可追溯的部分继续整理，缺页、截断、已删除或不可访问内容单列，仍缺的材料在批次补证单中统一提出。

### 3.3 官方网站

按内容职责读取当前官网，而不是直接套用历史规划中的 31 页：

| 页面组 | 整理重点 |
| --- | --- |
| 首页、About | 名称、定位、受众、品牌关系、当前公开承诺 |
| Brand Deals / Opportunities | 机会类型、注册与申请流程、提交审核、结算条件、限制 |
| MyyFinds | 商品页曝光收益的对象、参与方式、计量范围、限制和反作弊说明 |
| Find Your Lane、Free Value Report、课程等现有入口 | 当前公开能力、交付内容、适用范围；不能仅凭导航存在判定功能可用 |
| 服务协议、隐私与现有帮助页面 | 资格、授权、内容权利、费用与支付、退出申诉、责任边界 |
| 官网明确链接的 Newsroom、What's New、Academy、Blog | 只选与品牌事实、产品和政策有关的内容；泛行业教程不自动转为品牌知识 |

每页记录最终 URL、标题、正文位置、页面标示的发布时间/更新或生效日期、读取时间与快照。未标日期时保持未知，读取时间不代替生效日期。官网公开表述、实际功能运行情况和业务确认分别记录；本轮不注册账号、申请商单或操作支付来验证能力。

## 4. 从素材到知识的统一规则

### 4.1 保留完整追溯关系

使用以下关系组织材料，不新增一套采集或任务系统：

```text
原件 / 页面 / 帖子
    → 可定位的原文片段与读取版本
    → 带产品、对象、地区和时间条件的事实草稿
    → 现有 KB 条目
    → 复用共享事实的标准答案
    → 用户批次确认与版本记录
```

来源登记至少包含：本地文件或原 URL、发布主体、内容作者/供稿方、素材类型、原稿与转载关系、发布时间、生效时间、读取时间、可访问情况、快照与校验值、具体段落/单元格/图片位置。

条目整理表至少包含：原 KB ID、英文/中文路径、源版本与校验值、优先级、英文结论与完整中文对照、来源片段、适用产品/人群/地区/平台/语言、限制与例外、有效期、与旧内容的差异、证据缺口、拟负责岗位、批次决定与受影响答案。英文可独立使用，中文逐项对应；翻译不得删除条件或强化承诺。

### 4.2 分开记录表述、支持程度与批准

| 维度 | 记录方式 |
| --- | --- |
| 材料表达了什么 | 区分当前陈述、历史事实、规划、观点、宣传语、示例与数据主张 |
| 来源能够支持什么 | 逐项说明支持范围；公开出现只能证明曾这样表述，不能单独证明普遍效果、功能实际可用或现行政策完整 |
| 用户确认了什么 | 保留逐项或明确列表范围的决定；内部口径确认不消除缺证，也不自动允许外部发布 |

上述是整理字段，不新增业务对象状态枚举。计划使用 `proposed`；待业务确认的 legacy 条目继续使用其既有 `draft` 语义；正式对象的状态与批准证据沿用现有契约。

证据支持判断沿用用户旅程 Q11 与 Spec 0004 第 5 节：普通事实看适用的一方依据；能力/效果需要相应数据或案例；比较需要可核验的比较对象和独立依据；高风险承诺需要正式规则、范围和人工决定。多渠道重复同一品牌自述不增加独立证据数量。内部依据与可公开引用来源分开管理。

### 4.3 处理冲突与缺口

先比较是否为同一产品、人群、地区、活动和有效时期，再检查是否存在明确替代关系。当前规则解释优先核对适用的正式政策和业务确认；不能仅按网页更新时间、文件修改时间或发布渠道替用户决定现行事实。

仍无法解释的同范围冲突进入一张汇总表：两种表述、各自来源和日期、影响条目、建议核实的事实、需要的决定。仅暂停受影响结论，其余条目继续。新版本保留旧版本来源与适用期，不回写历史平台答案或原评估结果。

“未取得材料”“材料未提到”“当前明确不支持”“历史上支持”“待业务确认”分别记录。只有存在适用事实和依据、但缺少对外说明时，才归为内容缺口；无法证实事实先列为证据或确认缺口。
