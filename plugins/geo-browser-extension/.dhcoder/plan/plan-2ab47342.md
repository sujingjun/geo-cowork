# AI Agent 驱动的达人建联工作台 — Nuxt 4 Chrome 插件开发计划

## 产品定位

基于 wavith-extension-v1.2.2 的架构分析，使用 Nuxt 4 技术栈重新构建一款 AI Agent 驱动的达人建联工作台 Chrome 插件。核心能力对标 wavith：智能挖掘目标达人 → 智能发起私信触达 → 对话式沟通转化，同时以 AI Agent 为核心驱动引擎，替代 wavith 的纯脚本流程。

## 技术架构

### 技术栈选型
- **框架**: Nuxt 4 (`ssr: false`，SPA 模式，`nuxt generate` 输出静态资源)
- **UI**: Nuxt UI + Tailwind CSS
- **状态管理**: Pinia
- **AI Agent**: Nuxt AI (基于 `@nuxt/ai` 或自建 SSE 流式 Agent 服务端)
- **后端 API**: Nuxt Server Routes (Nitro) 作为 BFF 层，代理转发到真实后端
- **Chrome 插件打包**: `nuxt generate` → 自定义构建脚本组装 `manifest.json` + background/content/inject 脚本

## 核心功能模块

### 1. AI Agent 驱动引擎（核心差异点）

wavith 的流程是"用户手动配置参数 → 脚本执行"。本产品以 AI Agent 为中枢：

- **Agent 对话面板**: 用户用自然语言下达指令（如"帮我找美妆领域、粉丝1k-10k的达人，找50个"），Agent 自动解析意图、编排采集流程、返回结果
- **Agent 工具调用（Tool Use）**: Agent 可调用扩展能力：
  - `search_creators` — 搜索达人
  - `crawl_comments` — 抓取评论用户
  - `send_dm` — 发送私信
  - `get_creator_profile` — 获取达人详情
  - `create_message_template` — 生成文案
  - `check_outreach_status` — 查看触达状态
- **流式响应**: SSE 推送 Agent 思考过程和执行进度
- **自动跟进**: Agent 监听达人回复，自动生成跟进话术

### 2. 智能挖掘目标达人（对标 wavith 找达人）

- **网络拦截层** (`extension/inject.ts`): Hook `fetch` / `XMLHttpRequest`，拦截抖音 API 响应：
  - `/aweme/v1/web/search/item` — 视频搜索结果（提取 author 信息）
  - `/aweme/v1/web/comment/list` — 评论列表（提取评论用户 sec_uid）
  - `/aweme/v1/web/user/profile/other` — 用户主页 profile
  - `/aweme/v1/web/aweme/post` — 用户视频列表
- **数据提取与过滤** (`extension/background.ts`):
  - 从拦截数据中提取达人：sec_uid, nickname, follower_count, avatar, signature
  - 按粉丝量级、发布时间、互动率过滤
  - 客户端去重 + 服务端去重（对比已有候选池）
- **Agent 编排**: Agent 接收自然语言指令 → 解析为结构化参数 → 自动打开搜索页 → 拦截数据 → 过滤去重 → 入候选池

### 3. 智能发起私信触达（对标 wavith 私信触达）

- **私信发送流程** (`extension/background.ts`):
  - 打开达人主页 → 等待页面加载 → 点击私信按钮 → 等待输入框就绪 → 粘贴文案 → 点击发送
  - 限频检测：检测"给陌生人发送消息过于频繁"等关键词
  - 限频后自动切换账号（登出 → 重新登录）
- **文案模板系统**:
  - 变量占位：`{{昵称}}`, `{{领域}}`, `{{粉丝数}}` 等
  - A/B 多模板测试
  - 命中率回流统计（发送数 / 回复数）
- **Agent 驱动**: Agent 根据达人画像自动生成个性化文案，支持对话式微调

### 4. 对话式沟通转化（核心增强）

- **达人候选池视图**: 统一管理所有达人，状态跟踪（待发送/已发送/已回复/已转化）
- **对话面板**: 集成 AI Agent，支持：
  - 自然语言查询达人池（"给我看看粉丝5万以上的美妆达人"）
  - 对话式创建触达任务（"给这批达人发新品种草文案"）
  - 实时进度查看（Agent 汇报执行状态）
  - 自动回复跟进建议

### 5. Chrome 插件能力集成

- **Manifest V3 配置**: permissions (storage, tabs, scripting, webRequest), host_permissions (目标平台域名)
- **双入口**: Popup (`index.html`) + 管理页面 (`workbench.vue` 全屏标签页)
- **Content Script 桥接**: `content.ts` 在目标平台页面注入，转发消息到 background
- **Main World 注入**: `inject.ts` + `bridge.ts` 在页面主世界运行，拦截网络请求并提供可编程 API
- **Web 端兼容**: Nuxt 应用本身作为 Web 应用可独立运行，通过检测 `chrome.runtime` API 判断是否在插件环境中，降级为纯 API 模式

## 实施步骤

### 阶段一：项目初始化与基础架构
- 初始化 Nuxt 4 项目，配置 `ssr: false` + Nitro 静态输出

- 实现 `extension/inject.ts`：Hook fetch/XHR，拦截抖音 API 响应

- 实现 `server/api/creators/` 服务端接口：达人 CRUD、去重校验

- 实现 `server/api/agent/` 流式 SSE 接口

### 阶段五：私信触达系统
- 实现 `extension/background.ts` 私信发送流程（页面操作函数）

### 阶段六：对话转化与管理
- 实现 `app/pages/workbench.vue` 统一工作台
- 实现达人状态跟踪（待发送/已发送/已回复/已转化）
- 实现 Agent 自动跟进建议

### 阶段七：构建打包与测试
- 完善 `scripts/build-extension.ts`：`nuxt generate` → 组装 extension 目录
- 实现 Web 端 / 插件端环境自适应
- 编写测试用例
- Chrome `chrome://extensions` 加载测试

## 关键文件说明

- `nuxt.config.ts` — 配置 `ssr: false`, Nitro preset, 构建输出路径
- `extension/background.ts` — Service Worker，核心业务编排（采集、去重、发送、限频处理）
- `extension/inject.ts` — Main World 注入，Hook fetch/XHR 拦截抖音 API
- `extension/content.ts` — Content Script，页面 ↔ background 消息桥接
- `extension/bridge.ts` — Main World 注入，可编程调用 API（`window.CreatorWorkbench.call()`）
- `server/api/agent/` — AI Agent SSE 流式接口，Tool Use 编排
- `app/composables/useExtensionBridge.ts` — 封装 chrome.runtime 消息通信，支持 Web 端降级
- `app/composables/useAgent.ts` — Agent 流式对话，SSE 接收，Tool 执行状态展示
- `scripts/build-extension.ts` — 构建后处理：复制 manifest.json、icons 到 .output/public

## 与 wavith 的核心差异

| 维度 | wavith v1.2.2 | 本产品 |
|------|---------------|--------|
| 框架 | React (打包后) | Nuxt 4 (Vue 3) |
| 驱动方式 | 用户手动配置参数执行 | AI Agent 自然语言驱动 |
| 网络拦截 | inject.js (fetch/XHR hook) | inject.ts (同方案，TypeScript 重写) |
| 后端 | 独立后端 api-wavith.thiflow.com | Nuxt Server Routes BFF + 可选独立后端 |
| 对话转化 | 无 | AI Agent 对话式沟通转化 |
| 文案生成 | 手动模板 | Agent 自动生成个性化文案 |
| Web 端 | 仅插件 | 插件 + Web 端双模式 |
