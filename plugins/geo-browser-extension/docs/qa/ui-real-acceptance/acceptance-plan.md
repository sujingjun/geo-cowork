# Creator Workbench 真实 UI 验收计划

## 成功标准

仅当最新代码快照上的完整 S1-S10 真实操作轮次没有新缺陷、缺陷台账没有未关闭项、`pnpm test` 与 `pnpm build:extension:test` 均通过时，才可结束本轮验收。

## 当前边界

- 只使用 Chrome 中已经打开的 TikTok 公开页面和自然加载数据。
- 不新建后台采集标签页，不自动滚动、翻页、点赞、关注、评论或私信。
- 不读取、复制或保存 Cookie、令牌、密码、API Key 与 `.env` 值。
- 搜索场景需要用户批准一个关键词；未批准前记为 `BLOCKED`。
- 删除场景只允许使用本轮明确标记的测试记录，并在实际确认删除前再次取得用户确认。
- 截图包含账号或公开个人资料时只保存在系统临时目录，不提交仓库。

## 执行顺序

1. 冻结路径、分支、HEAD、dirty、remote、Chrome、服务与门禁基线。
2. 刷新 `.output/extension` 中的已加载扩展并确认扩展状态。
3. 逐项执行 S1-S10，记录预期、实际、证据与控制台摘要。
4. 完成本轮缺陷盘点后按领域创建独立修复任务。
5. 审查并集成修复，重新运行门禁并刷新扩展。
6. 从 S1 开始执行新的完整验收轮，直到零缺陷。

## 证据规则

- 仓库只保存脱敏文字记录。
- 未脱敏截图位于系统临时目录，仅记录受控路径。
- 不抓取 HAR；需要网络证据时另行说明风险并脱敏。
