# Production Deployment

本文档记录 `geo-site-building-web` 的线上发布流程。当前线上数据库使用 Supabase 项目：

https://supabase.com/dashboard/project/juoxvnmjnnxsrpagxhcj

## 发布拓扑

- 应用托管：Vercel Project `geo-site-building-web`
- 数据库：Supabase Postgres
- 运行时：Nuxt 4 / Nitro Vercel preset
- 文件上传：NuxtHub Blob，Vercel 上使用 Vercel Blob
- AI：优先使用 Vercel AI Gateway，也支持 OpenAI、Anthropic、Google、DeepSeek 直连

## Supabase 连接串

Vercel Serverless/Edge 场景优先使用 Supabase Dashboard `Connect` 面板中的 **Transaction pooler** 连接串，并作为 `DATABASE_URL` 写入 Vercel Production 环境变量。

原因：

- Supabase 官方建议 serverless 或 edge function 使用 transaction mode pooler。
- Transaction pooler 端口通常是 `6543`。
- Transaction mode 不支持 prepared statements；项目里的自定义脚本已经用 `postgres(connectionString, { prepare: false })` 关闭 prepared statements。

示例格式，密码和 region 以 Supabase Dashboard 为准：

```env
DATABASE_URL=postgres://postgres.juoxvnmjnnxsrpagxhcj:[YOUR-PASSWORD]@aws-[REGION].pooler.supabase.com:6543/postgres
```

如果要执行迁移、备份或 `pg_dump` 等长连接操作，可在本机临时使用 Direct connection：

```env
DATABASE_URL=postgresql://postgres:[YOUR-PASSWORD]@db.juoxvnmjnnxsrpagxhcj.supabase.co:5432/postgres
```

## Vercel 环境变量

生产环境至少需要：

```env
DATABASE_URL=
# 或 POSTGRES_URL / POSTGRESQL_URL
NUXT_SESSION_PASSWORD=
NUXT_PUBLIC_SITE_URL=
DEEPSEEK_API_KEY=
```

按功能补充：

```env
BLOB_READ_WRITE_TOKEN=
NUXT_OAUTH_GITHUB_CLIENT_ID=
NUXT_OAUTH_GITHUB_CLIENT_SECRET=
NUXT_OAUTH_GOOGLE_CLIENT_ID=
NUXT_OAUTH_GOOGLE_CLIENT_SECRET=
OPENAI_API_KEY=
OPENAI_BASE_URL=
ANTHROPIC_API_KEY=
ANTHROPIC_BASE_URL=
GOOGLE_GENERATIVE_AI_API_KEY=
GOOGLE_BASE_URL=
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=
```

写入 Vercel。Supabase/Vercel 集成创建的 `POSTGRES_URL` 有时可用于云端构建和运行时，但本机 `vercel pull` 只会拉到空值；如果要走本地 prebuilt 发布，请另行写入可本地读取的 `DATABASE_URL`。

```bash
pnpm dlx vercel@54.14.0 env add DATABASE_URL production
pnpm dlx vercel@54.14.0 env add NUXT_SESSION_PASSWORD production
pnpm dlx vercel@54.14.0 env add NUXT_PUBLIC_SITE_URL production
pnpm dlx vercel@54.14.0 env add DEEPSEEK_API_KEY production
```

更新后拉取并检查：

```bash
pnpm vercel:pull:prod
pnpm check:env:production
```

## 手动发布

标准生产发布命令：

```bash
pnpm deploy:prod
```

该命令会依次执行：

1. 拉取 Vercel Production 环境变量。
2. 校验生产必填变量，尤其是 `DATABASE_URL` / `POSTGRES_URL` / `POSTGRESQL_URL`。
3. 运行 Nuxt typecheck。
4. 上传源码并交给 Vercel 云端执行 Production 构建和发布。

默认使用云端构建，是因为 Vercel 集成密钥可能无法通过 `vercel pull` 回读到本机。若你已经显式配置了本地可读取的 `DATABASE_URL`，也可以走 prebuilt：

```bash
pnpm deploy:prod:prebuilt
```

单步排查：

```bash
pnpm vercel:pull:prod
pnpm check:env:production
pnpm typecheck
pnpm vercel:deploy:prod
```

## CI 发布

GitHub Actions 工作流：

```text
.github/workflows/deploy-production.yml
```

仓库 Secrets 需要配置：

```env
VERCEL_TOKEN=
VERCEL_ORG_ID=
VERCEL_PROJECT_ID=
```

`VERCEL_ORG_ID` 和 `VERCEL_PROJECT_ID` 可从本机 `.vercel/project.json` 获取；不要提交 `.vercel` 目录。

## 验证

发布完成后检查：

```bash
pnpm dlx vercel@54.14.0 ls geo-site-building-web
pnpm dlx vercel@54.14.0 inspect <deployment-url>
curl -I -L <deployment-url>
```

如果 `curl` 返回 `401` 且页面来自 Vercel，通常是 Vercel Deployment Protection/SSO 生效，不代表应用构建失败。需要在 Vercel Dashboard 中确认生产域名保护策略。

## 访问无响应排查

先区分请求卡在 Vercel 外层、网络代理，还是应用运行时：

```bash
pnpm dlx vercel@54.14.0 ls geo-site-building-web
pnpm dlx vercel@54.14.0 inspect https://geo-site-building-web.vercel.app
pnpm dlx vercel@54.14.0 logs --since 1h --level error
curl -I -L --connect-timeout 5 --max-time 12 https://geo-site-building-web.vercel.app
dig +short geo-site-building-web.vercel.app
```

判断方式：

- Dashboard 显示 Production Deployment 为 `Ready`，但最新 deployment 显示 `Blocked` 或 CLI 显示 `UNKNOWN`：说明最新一次部署没有接管生产，生产仍指向上一次 Ready deployment。
- `curl` 返回 Vercel 的 `401`，且有 `_vercel_sso_nonce` 等 header：说明 Deployment Protection/SSO 在应用之前拦截了请求，应用函数不会产生业务日志。
- Vercel Observability 里 Edge Requests / Function Invocations 接近 0，且 `vercel logs` 没有运行时错误：通常不是 Nuxt runtime 先崩溃，而是请求没进入应用。
- `dig` 返回 `198.18.0.0/16` 地址段：这是 Clash/Shadowrocket 常见 fake-ip 段，不是 Vercel 真实边缘地址。如果浏览器一直转圈，优先检查代理规则、fake-ip DNS 缓存和 `vercel.app` 分流策略。

处理顺序：

1. 在 Vercel Dashboard 确认 Production Deployment 是否为 `Ready`，必要时 rollback 到最近的 Ready deployment。
2. 如果需要公网访问，在 Vercel Project Settings 中关闭或调整 Production 的 Deployment Protection；如果只给团队访问，保留保护并使用已登录账号访问。
3. 如果本机访问主域名超时，重启 Shadowrocket/Clash DNS，清理 fake-ip 缓存，并确认 `DOMAIN-SUFFIX,vercel.app` 走可用线路。
4. 补齐 Production 环境变量后重新发布，避免放开访问后应用因为缺少数据库、会话或 AI key 再次不可用。

## 常见问题

### 本地 prebuilt 构建日志显示 PGlite driver

说明本地构建没有拿到可读取的 `DATABASE_URL` / `POSTGRES_URL` / `POSTGRESQL_URL`。如果 Vercel 云端已有 Supabase 集成变量，优先使用云端构建：

```bash
pnpm deploy:prod
```

如果必须本地 prebuilt，写入可回读的 `DATABASE_URL` 后再发布：

```bash
pnpm dlx vercel@54.14.0 env add DATABASE_URL production
pnpm vercel:pull:prod
pnpm check:env:production
pnpm deploy:prod:prebuilt
```

### Supabase 密码认证失败

在 Supabase Dashboard 的 `Connect` 面板重新复制连接串，确认密码已 URL encode。必要时在 Project Settings 中重置 database password。

### Transaction pooler 报 prepared statement 错误

Transaction mode 不支持 prepared statements。应用侧如果新增直接使用 `postgres` 的脚本，请保持：

```js
postgres(connectionString, { prepare: false })
```

### 首次迁移

`vercel build --prod` 会使用 Production 环境变量构建，并由 NuxtHub 包含/应用数据库迁移。发布前务必先确认 `pnpm check:env:production` 通过，避免迁移落到本地 PGlite。
