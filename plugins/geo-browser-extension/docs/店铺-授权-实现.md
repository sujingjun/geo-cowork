# 店铺授权实现

本文档记录当前仓库的多平台店铺授权与商品同步实现。当前已支持 Amazon 卖家账号授权，以及 Shopify 店铺 OAuth 授权与商品同步。

## 支持范围

- Amazon：生产环境支持 Selling Partner OAuth 授权；sandbox 环境使用门户生成的沙箱 refresh token；商品同步仅需 LWA access token，无需 AWS IAM / SigV4 签名。
- Shopify：支持 OAuth 授权、店铺落库、商品同步到通用 `products` 模型、参与 AI 站点生成。

## Amazon App 客户端与服务的区别

- **App 客户端**是 SP-API 程序身份，包含 Application ID、LWA client id/client secret、环境和授权 token。代码通过它获得 access token 并调用 API。生产客户端还关联审核通过的角色。
- **服务**是解决方案提供商向 Amazon 卖家展示的商业服务条目，用于资质审核、商品信息和获客展示。它不是 API 凭证，也不会为 App 客户端授予 Catalog、Listings 等接口权限。
- 沙箱 App 客户端可调用 Amazon 提供的静态 mock API；它不能读取真实卖家商品。真实店铺同步必须使用审核通过的生产 App 客户端，并由卖家完成 OAuth 授权。

## Amazon 授权流程

1. 用户点击 `StoreAuthButton`。
2. 前端调用 `POST /api/stores`。
3. 服务端校验登录状态和 Amazon 配置，生成 `state`，写入 `amazon_oauth_state` HttpOnly cookie。
4. `AMAZON_SP_API_ENVIRONMENT=production` 时，服务端返回 Seller Central 授权 URL。
5. 生产环境下，前端在弹窗中打开授权 URL。
6. Amazon 先访问应用的 log-in URI `/auth/amazon`，带回 `amazon_callback_uri`、`amazon_state`、`selling_partner_id`。
7. 服务端校验本地 `state` cookie，再带 `amazon_state`、本地 `state`、`redirect_uri` 跳回 Amazon callback URI。
8. Amazon 最终回调 redirect URI `/auth/amazon`，带回 `spapi_oauth_code`、`state`、`selling_partner_id`。
9. 服务端校验 `state`，用 LWA client id/secret 换取 access token 和 refresh token。
10. `AMAZON_SP_API_ENVIRONMENT=sandbox` 时，服务端返回本地 `/auth/amazon` 沙箱回调 URL，不跳 Seller Central；回调使用 `AMAZON_SP_API_SANDBOX_REFRESH_TOKEN` 换取真实的一小时 LWA access token。
11. 服务端把授权信息写入 `stores` 表，弹窗通知主窗口并关闭。

## Amazon 必需配置

```env
NUXT_PUBLIC_SITE_URL=https://geo-site-building-web.vercel.app
NUXT_OAUTH_AMAZON_CLIENT_ID=
NUXT_OAUTH_AMAZON_CLIENT_SECRET=
AMAZON_SP_API_APPLICATION_ID=
AMAZON_SP_API_ENVIRONMENT=sandbox
AMAZON_SP_API_SANDBOX_REFRESH_TOKEN=
AMAZON_SP_API_AUTH_VERSION=
AMAZON_SELLER_CENTRAL_AUTHORIZE_URL=https://sellercentral.amazon.com/apps/authorize/consent
AMAZON_SP_API_REGION=us-east-1
AMAZON_MARKETPLACE_ID=ATVPDKIKX0DER
AMAZON_SP_API_ENDPOINT=
```

`NUXT_OAUTH_AMAZON_CLIENT_ID` 和 `NUXT_OAUTH_AMAZON_CLIENT_SECRET` 是 Selling Partner App 关联的 Login with Amazon 凭证。`AMAZON_SP_API_APPLICATION_ID` 是 Amazon Selling Partner App 的 application id。沙箱环境还必须配置同一沙箱客户端创建的 `AMAZON_SP_API_SANDBOX_REFRESH_TOKEN`。

如果 Amazon Selling Partner App 还处于 Draft 状态，把 `AMAZON_SP_API_AUTH_VERSION` 设置为 `beta`。应用正式发布后保持为空。

`AMAZON_SP_API_ENVIRONMENT=sandbox` 用于开发阶段调用 Amazon 官方 SP-API Sandbox。`AMAZON_SP_API_ENDPOINT` 留空时，服务端会按 `AMAZON_SP_API_ENVIRONMENT` 和 `AMAZON_SP_API_REGION` 自动选择 endpoint；只有需要临时覆盖时才手动填写。

## Amazon 回调地址

在 Amazon Developer / Seller Central app 配置里添加。当前实现使用同一个端点同时承担 Log-in URI 和 Redirect URI：

```text
Log-in URI: https://geo-site-building-web.vercel.app/auth/amazon
Redirect URI: https://geo-site-building-web.vercel.app/auth/amazon
```

本地开发时：

```text
Log-in URI: http://localhost:3000/auth/amazon
Redirect URI: http://localhost:3000/auth/amazon
```

## Amazon 不同区域

北美默认配置：

```env
AMAZON_SP_API_ENVIRONMENT=production
AMAZON_SELLER_CENTRAL_AUTHORIZE_URL=https://sellercentral.amazon.com/apps/authorize/consent
AMAZON_SP_API_REGION=us-east-1
AMAZON_MARKETPLACE_ID=ATVPDKIKX0DER
AMAZON_SP_API_ENDPOINT=
```

欧洲和远东需要换成对应 Seller Central 授权域名、SP-API endpoint、marketplace id。

自动 endpoint 映射：

| 环境 | `us-east-1` 北美 | `eu-west-1` 欧洲 | `us-west-2` 远东 |
| --- | --- | --- | --- |
| `sandbox` | `https://sandbox.sellingpartnerapi-na.amazon.com` | `https://sandbox.sellingpartnerapi-eu.amazon.com` | `https://sandbox.sellingpartnerapi-fe.amazon.com` |
| `production` | `https://sellingpartnerapi-na.amazon.com` | `https://sellingpartnerapi-eu.amazon.com` | `https://sellingpartnerapi-fe.amazon.com` |

## Amazon Sandbox 测试流程

开发阶段不需要直接使用真实店铺商品数据来验证 SP-API 调用链路。项目在 `AMAZON_SP_API_ENVIRONMENT=sandbox` 下会走本地沙箱授权回调，创建 `Amazon Sandbox Test Store` 测试店铺，不会跳转到真实 Seller Central 店铺授权。Amazon 官方 Sandbox endpoint 会返回固定测试响应，适合验证 LWA access token、endpoint、错误处理和商品同步落库链路。

本地推荐配置：

```env
NUXT_PUBLIC_SITE_URL=http://localhost:3000
AMAZON_SP_API_ENVIRONMENT=sandbox
AMAZON_SP_API_SANDBOX_REFRESH_TOKEN=Atzr|...
AMAZON_SP_API_AUTH_VERSION=beta
AMAZON_SP_API_REGION=us-east-1
AMAZON_MARKETPLACE_ID=ATVPDKIKX0DER
AMAZON_SP_API_ENDPOINT=
```

操作步骤：

1. 在解决方案提供商门户找到沙箱 App 客户端，确认 LWA client id/client secret 已写入 `.env`。
2. 在该客户端“操作”下拉菜单选择 **Create Token**，在 Sandbox Testing 页面再次创建并复制 `Atzr|...` refresh token。
3. 设置 `AMAZON_SP_API_ENVIRONMENT=sandbox` 和 `AMAZON_SP_API_SANDBOX_REFRESH_TOKEN`，并让 `AMAZON_SP_API_ENDPOINT` 留空。
4. 确认 LWA client id、LWA client secret、refresh token、SP-API application id 全都来自同一个沙箱 App 客户端。
5. 重启开发服务器：`pnpm dev`，删除旧的 `Amazon Sandbox Test Store` 或对其重新授权。
6. 登录本地应用并连接 Amazon；回调会用 refresh token 换取 access token，再保存测试店铺。
7. 执行商品同步。请求会命中 Listings Items 静态沙箱示例并返回固定的行李箱测试商品。

注意：Sandbox 只保证接口调用流程，不代表真实店铺库存、价格或完整目录数据。要验证真实商品同步，才把 `AMAZON_SP_API_ENVIRONMENT` 改为 `production` 并重启服务。

## Amazon 商品同步说明

SP-API 最新授权规则下，OAuth 登录获取的 LWA access token 即可直接调用数据接口，无需 AWS IAM 凭证或 SigV4 签名。服务端使用 Listings Items API 的 `searchListingsItems` 同步该卖家的商品；Catalog Items API 是 Amazon 全局目录搜索，不适合枚举某个卖家的商品。

商品同步变量：无需额外 AWS 配置，仅需 OAuth 授权完成后的 LWA 凭证。

- `AMAZON_SP_API_REGION`：北美默认 `us-east-1`，并与 `AMAZON_SP_API_ENDPOINT=https://sellingpartnerapi-na.amazon.com` 配套。
- `POST /api/stores/[id]/sync` 在缺少 LWA 授权配置时会返回明确错误。配置后需要重启 Nuxt dev server，让 `runtimeConfig` 重新读取 `.env`。

## Amazon Sandbox 403 排查

错误正文包含 `The access token you provided is revoked, malformed or invalid` 时，说明传入的不是 LWA 签发的 access token。检查是否仍在使用旧代码写死的 `sandbox-access-token`，以及沙箱 refresh token 是否与当前 LWA client id/client secret 属于同一个客户端。

如果 token 有效但静态沙箱仍拒绝请求，核对请求参数是否匹配对应 OpenAPI 模型的 `x-amzn-api-sandbox.static.request.parameters`。静态沙箱按参数匹配 mock，不会按任意条件搜索真实商品。

## 本次修复的原因与影响

- 原因：旧实现伪造沙箱 access/refresh token，并用 Catalog Items API 无条件搜索商品，导致 403，且语义上无法正确同步卖家自己的 listing。
- 影响：沙箱连接现在需要新增 `AMAZON_SP_API_SANDBOX_REFRESH_TOKEN`；已有沙箱测试店铺必须重新授权。生产授权流程保持不变，商品读取改为 Listings Items API。

## Shopify 授权流程

1. 用户在 `StoreAuthButton` 里选择 `Shopify` 并输入店铺域名。
2. 前端调用 `POST /api/stores`，请求体携带 `platform=shopify` 和 `shopDomain`。
3. 服务端生成 `state`，写入 `shopify_oauth_state` HttpOnly cookie，并返回 Shopify 授权 URL。
4. 前端在弹窗中打开授权 URL。
5. Shopify 回调 `/auth/shopify`，带回 `code`、`shop`、`state`、`hmac`。
6. 服务端校验 state、shop domain 和 HMAC。
7. 服务端使用 access token exchange 获取永久 token，并读取店铺信息。
8. 服务端把店铺信息写入 `stores` 表，`platform='shopify'`，并保存 `shopDomain`、`scopes` 等字段。
9. 用户可在 `/sites` 页面手动触发该店铺的商品同步。

## Shopify 必需配置

```env
NUXT_PUBLIC_SITE_URL=https://geo-site-building-web.vercel.app
NUXT_OAUTH_SHOPIFY_CLIENT_ID=
NUXT_OAUTH_SHOPIFY_CLIENT_SECRET=
NUXT_OAUTH_SHOPIFY_SCOPES=read_products
SHOPIFY_API_VERSION=2024-10
```

默认 scope 仅要求 `read_products`。如果后续扩展更多 Shopify Admin API 能力，再增加 scope。

## Shopify 回调地址

```text
Redirect URI: https://geo-site-building-web.vercel.app/auth/shopify
```

本地开发时：

```text
Redirect URI: http://localhost:3000/auth/shopify
```

输入店铺域名时，前端支持 `your-store` 和 `your-store.myshopify.com` 两种形式，服务端会统一规范化为 `*.myshopify.com`。

## Shopify 商品同步说明

- 商品同步入口：`POST /api/stores/[id]/sync`
- 服务端会根据 `stores.platform` 自动分流到 Amazon 或 Shopify 同步实现。
- Shopify 商品会映射到共享 `products` 模型中的这些字段：
  - `externalProductId`
  - `platformHandle`
  - `productUrl`
  - `vendor`
  - `productType`
  - `tags`
  - `variants`
  - `rawData`
- 站点生成时会校验商品必须归属于当前用户已连接店铺，避免跨用户或跨未授权店铺混用。

## 常见问题

### Amazon authorization is not configured

说明缺少 LWA client id、LWA client secret 或 SP-API application id。补齐 Vercel Production 环境变量后重新部署。

### Amazon authorization state is invalid or expired

授权弹窗超过 10 分钟、cookie 被清理、或回调 state 不匹配。重新点击“连接亚马逊卖家账号”。

### Failed to complete Amazon authorization

通常是 LWA token exchange 失败。检查：

- 回调地址是否与 Amazon app 配置完全一致。
- LWA client id/secret 是否来自同一个 Selling Partner App。
- `AMAZON_SP_API_APPLICATION_ID` 是否正确。

### 商品同步提示需要 LWA 授权配置

授权登录已完成，但 SP-API 数据接口还没配置 LWA client id/secret。补齐 `NUXT_OAUTH_AMAZON_CLIENT_ID` / `NUXT_OAUTH_AMAZON_CLIENT_SECRET` 后才能同步真实商品。

### Sandbox 没有返回真实商品

这是预期行为。Amazon SP-API Sandbox 返回固定测试响应，适合验证 LWA access token、endpoint 和错误处理；真实商品需要切回 `AMAZON_SP_API_ENVIRONMENT=production` 后再同步。

### Shopify authorization signature is invalid

通常是 Shopify callback 参数被改写、应用 secret 配错、或者回调地址不一致。检查：

- `NUXT_OAUTH_SHOPIFY_CLIENT_SECRET` 是否与当前 Shopify App 一致。
- Shopify App 的 redirect URI 是否与 `NUXT_PUBLIC_SITE_URL/auth/shopify` 完全一致。
- 是否通过代理或中间层改写了 query 参数。

### Shopify authorization shop mismatch

说明用户输入的店铺域名和回调里的 `shop` 不一致，或输入了错误店铺。重新发起授权并确认域名。

### Shopify 店铺已授权但没有商品

检查：

- Shopify 店铺是否有已发布商品。
- App scope 是否至少包含 `read_products`。
- `/sites` 页面是否已对对应店铺执行“同步商品”。
