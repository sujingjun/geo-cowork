# 多平台授权与站点路由拆分设计

## 背景

当前仓库已经支持 Amazon 与 Shopify 两个平台的店铺授权与商品同步，但交互仍然偏“单入口 + 轻平台区分”：

- 授权入口集中在一个组件中，通过下拉切换平台，不够突出平台边界。
- 授权成功后的状态反馈主要依赖 toast，缺少平台级持续状态展示。
- `/sites` 同时承载“系统内生成并托管的 GEO 展示站点”和未来更复杂的 Shopify 站外站点，信息架构容易继续混乱。

用户希望把“站内站点”和“站外 Shopify 站点”明确区分，并将 Shopify 外站定义为独立产品线：后续将支持 Shopify CLI / MCP、主题、模板，以及 Amazon / Shopify 商品来源配置。

## 目标

### 产品目标

- 让 Amazon 与 Shopify 的授权入口、输入项、状态和后续动作都明显分区。
- 让用户在“我的站点”里清楚区分站内 GEO 站点与 Shopify 站外站点。
- 为未来 Shopify CLI / MCP、主题、模板、商品来源混合配置预留清晰的信息架构。

### 实现目标

- 保持现有 Nuxt / Nuxt UI / composable 模式，不做无关重构。
- 尽量复用现有 `stores`、`sites`、`products` 结构，在最小必要范围内增加站点类型能力。
- 保留现有 Amazon / Shopify 授权和商品同步能力，只改交互、路由和类型分流。

## 非目标

- 本次不直接实现完整 Shopify CLI / MCP 发布链路。
- 本次不实现 Shopify 外站的完整主题编辑器或模板市场。
- 本次不重做 AI 生成流程，只做创建入口与站点类型分流。
- 本次不做大规模数据迁移或拆分成多张全新站点表。

## 关键决策

### 1. 店铺授权改为双 Tab，而不是下拉切换

授权区域采用明确的两标签结构：

- `Amazon 授权`
- `Shopify 授权`

每个标签页只展示自身平台所需内容：

- Amazon：平台说明、授权按钮、授权状态、同步状态
- Shopify：店铺域名输入、授权按钮、授权状态、同步状态

这样可以把“平台切换”从次要表单控件升级为一等信息架构，降低误操作，也便于后续各自扩展独有配置。

### 2. 授权状态做成平台面板状态，而不是只靠 toast

授权成功后，状态应持续显示在对应面板中，包括：

- 是否已授权
- 已连接的店铺名称 / 域名 / 平台标识
- 最近一次同步结果或同步入口

toast 仍保留，但只作为瞬时反馈；真正的产品状态以页面中的平台卡片为准。

### 3. `/sites` 变为导航页，站内站点和 Shopify 外站拆为独立产品线

站点路由分为两条主线：

- `站内站点`
  - `/sites/internal`
  - `/sites/internal/[slug]`
- `Shopify 站外站点`
  - `/sites/shopify`
  - `/sites/shopify/[slug]`

`/sites` 不再承担所有列表内容，而是变成站点中心 / 分发页，让用户选择进入哪条产品线。

### 4. 站点数据继续共用 `sites` 主模型，但新增类型字段

推荐在现有 `sites` 数据模型中新增站点类型字段，例如：

- `internal`
- `shopify-external`

原因：

- 当前两类站点仍然共享标题、slug、SEO、模板、状态、关联商品等基础概念。
- 立即拆成两套站点主表会增加复杂度，且当前产品能力尚未发展到需要完全物理分表。
- 未来 Shopify 外站若需要更多专属配置，可以增加扩展配置字段或扩展表，而不是现在就过度设计。

### 5. Shopify 站外站点视为独立产品线，不等于“商品来源是 Shopify”

站外 Shopify 站点的定义不是“商品来自 Shopify”这么简单，而是：

- 面向 Shopify 店铺个性化定制
- 后续对接 Shopify CLI / MCP
- 支持主题与模板
- 支持 Amazon / Shopify / 混合商品来源

因此其路由、列表、空状态、创建入口都应独立于站内 GEO 站点，而不能只作为 `/sites` 的一个过滤条件埋在内部。

## 信息架构

## 授权区域

### 页面层

- `StoreAuthPrompt.vue` 作为总容器，负责：
  - 展示“需要授权店铺”整体说明
  - 呈现平台 tabs
  - 调用子面板组件

### 子面板层

- `AmazonStoreAuthPanel.vue`
- `ShopifyStoreAuthPanel.vue`

每个面板职责单一：

- 读取该平台相关店铺
- 发起该平台授权
- 展示该平台状态和同步入口
- 展示该平台错误信息

### composable 层

`useStores()` 扩展为提供平台级衍生状态：

- `amazonStores`
- `shopifyStores`
- `hasAmazonStore`
- `hasShopifyStore`
- `defaultAmazonStore`
- `defaultShopifyStore`

必要时增加平台同步状态管理，但不把复杂 UI 状态全部堆进 composable。

## 站点路由

### `/sites`

作为站点中心页，展示两张产品卡：

- 站内站点
- Shopify 站外站点

每张卡展示：

- 产品说明
- 当前数量摘要
- 进入列表按钮

### `/sites/internal`

只展示系统内部生成并托管的 GEO 展示站点：

- 列表
- 状态
- 商品数
- 进入详情
- 创建入口

### `/sites/shopify`

只展示 Shopify 站外站点：

- 现阶段先展示列表、空状态、未来能力说明
- 后续承接 Shopify CLI / MCP 创建流
- 可展示“已连接 Shopify 店铺”作为入口前置条件

### 详情页

- `/sites/internal/[slug]`：沿用当前站点详情预览能力
- `/sites/shopify/[slug]`：为 Shopify 外站预留独立详情页与配置视图

短期内如果 Shopify 外站详情能力尚未完整，可先做最小详情或占位页，但路由必须先拆开。

## 创建流设计

### 站内站点

- 保持当前 AI 生成站点链路
- 聊天首页检测到“需要建站”时，可以先引导到 `/sites`
- 用户再进入 `站内站点` 产品线创建

### Shopify 站外站点

第一阶段创建入口先做成独立入口页，包含：

- 选择店铺
- 选择主题
- 选择模板
- 选择商品来源：Amazon / Shopify / 混合

如果当前实现阶段先不接入完整创建链路，则最小版本应至少具备：

- 独立路由
- 独立空状态
- 明确“后续支持 Shopify CLI / MCP 发布”的说明

## 数据流与后端影响

### 店铺 API

`/api/stores` 返回结果需要足够支撑平台状态面板：

- 平台
- 店铺名
- 域名 / 店铺标识
- scopes
- 授权时间
- 最近同步时间（若已有或建议补充）

### 站点 API

`/api/sites` 增加按站点类型过滤能力，例如查询参数：

- `type=internal`
- `type=shopify-external`

`/api/sites/[slug]` 也需要在返回结果中明确站点类型，供详情路由校验。

### 旧路由兼容

若现有 `/sites/[slug]` 已被使用，建议做过渡处理：

- 根据站点类型重定向到 `/sites/internal/[slug]` 或 `/sites/shopify/[slug]`

这样能避免已有链接直接失效。

## 错误处理

- 平台授权失败要留在对应 tab 内展示，不要只依赖 toast。
- Shopify tab 的域名输入错误要只影响 Shopify，不干扰 Amazon。
- Amazon 未授权不阻塞 Shopify 外站列表浏览，但会影响使用 Amazon 商品作为来源。
- Shopify 外站若需要店铺前置条件，空状态要明确告诉用户先连接 Shopify 店铺。

## 测试与验证

### 交互验证

- Tab 切换清晰，Amazon / Shopify 各自状态独立。
- 授权后，对应平台面板展示已授权状态。
- 同步商品入口作用于对应平台店铺。

### 路由验证

- `/sites` 仅做分发，不再混合展示两类站点列表。
- `/sites/internal` 只出现站内站点。
- `/sites/shopify` 只出现 Shopify 外站。
- 旧 `/sites/[slug]` 可正确跳转或兼容。

### 数据验证

- 站点列表 API 可按类型过滤。
- 站点详情返回类型信息。
- 前端列表与详情不会把 Shopify 外站误当成站内站点处理。

## 分阶段实施建议

### 阶段 1：授权 UI 重构

- tabs + 双平台面板
- 平台授权状态持久展示
- 平台同步入口与状态

### 阶段 2：站点路由拆分

- `/sites` 分发页
- `/sites/internal` 与 `/sites/shopify` 列表
- 内站详情迁移
- 旧路由兼容

### 阶段 3：Shopify 外站独立创建流

- 主题 / 模板 / 商品来源选择
- Shopify CLI / MCP 对接入口
- 外站详情页逐步增强

## 风险与权衡

- 若现在直接把 Shopify 外站做成完全独立数据模型，会拖慢当前交付；因此先共用 `sites` 主模型更合适。
- 若继续把两类站点混在 `/sites` 下，只靠筛选或 tab 区分，未来产品语义会越来越模糊；因此推荐直接拆成独立产品线。
- 授权 UI 若不拆子面板，后续 Amazon / Shopify 特有配置会继续挤在单文件里，维护成本会上升。

## 结论

本次改造应围绕两个主轴展开：

1. 店铺授权从“单入口切平台”升级为“平台级 tabs + 独立状态面板”
2. 站点体系从“单一路由混合承载”升级为“站内站点 / Shopify 站外站点”两条独立产品线

这样既能改善当前多平台使用体验，也能为 Shopify CLI / MCP、主题、模板、混合商品来源等后续能力留下清晰演进空间。
