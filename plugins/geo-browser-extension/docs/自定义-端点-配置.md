# 自定义 LLM 端点配置指南

## 问题说明

当使用自定义 LLM 端点（如 `https://llm.dhcoder.net`）时，某些 AI SDK 的高级功能可能不兼容：

### 不兼容的功能

1. **Web Search 工具** - `openai.tools.webSearch()` 和 `anthropic.tools.webSearch_20250305()`
   - 这些是 AI SDK 提供的内置工具，依赖特定的后端实现
   - 自定义端点可能不支持这些工具的 API 格式

2. **Reasoning Summary** - OpenAI 的推理总结功能
   - `reasoningSummary` 仅支持 OpenAI 的推理模型（o1、o3 系列）
   - 大多数模型不支持此功能

3. **模型名称映射** - 不同端点可能使用不同的模型名称
   - 标准名称：`gpt-4o`, `gpt-4.1`
   - 自定义端点可能使用：`gpt-4`, `gpt-4-turbo`

## 解决方案

### 已自动处理的问题

项目已经自动检测自定义端点并禁用不兼容的功能：

1. **Web Search 自动禁用**
   - 检测到自定义端点时，自动禁用 `web_search` 工具
   - 用户仍可使用其他工具：`get_products`, `generate_site`, `chart`, `weather`

2. **Reasoning Summary 已移除**
   - 已从配置中移除 `reasoningSummary`
   - 避免非推理模型报错

### 环境变量配置

```bash
# .env 文件

# 使用自定义 LLM 端点
OPENAI_BASE_URL=https://llm.dhcoder.net
OPENAI_API_KEY=your-api-key

ANTHROPIC_BASE_URL=https://llm.dhcoder.net
ANTHROPIC_API_KEY=your-api-key

# 可选：强制启用或禁用 Web Search（默认：自定义端点下自动禁用）
# NUXT_AI_ENABLE_WEB_SEARCH=false
```

### 配置说明

#### 自定义端点检测

系统会自动检测以下配置来判断是否使用自定义端点：
- `OPENAI_BASE_URL` 是否设置
- `ANTHROPIC_BASE_URL` 是否设置
- `GOOGLE_BASE_URL` 是否设置

#### Web Search 控制

Web Search 工具在以下情况下**自动禁用**：
1. 检测到任何自定义端点配置
2. 环境变量 `NUXT_AI_ENABLE_WEB_SEARCH=false`

Web Search 工具在以下情况下**启用**：
1. 使用官方 API（无自定义端点）
2. 明确设置 `NUXT_AI_ENABLE_WEB_SEARCH=true`（不推荐，除非确认兼容）

## 功能对比

### 官方端点 vs 自定义端点

| 功能 | 官方端点 | 自定义端点 |
|------|---------|-----------|
| 基础对话 | ✅ 支持 | ✅ 支持 |
| 工具调用（get_products, generate_site, chart, weather） | ✅ 支持 | ✅ 支持 |
| Web Search | ✅ 支持 | ❌ 自动禁用 |
| Reasoning Summary | ❌ 仅推理模型 | ❌ 已移除 |
| 多模态输入（图片） | ✅ 支持 | ⚠️ 视端点而定 |
| 流式响应 | ✅ 支持 | ✅ 支持 |

## 模型名称映射

### 常见模型映射

如果你的自定义端点使用不同的模型名称，可能需要调整：

| 标准名称 | 可能的自定义名称 |
|----------|-----------------|
| `gpt-4o` | `gpt-4`, `gpt-4-turbo`, `gpt-4-vision` |
| `gpt-4.1` | `gpt-4-turbo`, `gpt-4-1106-preview` |
| `gpt-4o-mini` | `gpt-4o-mini`, `gpt-3.5-turbo` |
| `claude-3-7-sonnet-20250219` | `claude-3-5-sonnet-20241022` |

### 如何调整

1. 查看你的自定义端点支持的模型列表
2. 修改 `shared/utils/models.ts` 中的模型定义
3. 更新 `value` 字段为端点支持的模型名称

## 测试配置

### 测试步骤

1. **检查环境变量**
   ```bash
   pnpm check:env
   ```

2. **启动开发服务器**
   ```bash
   pnpm dev
   ```

3. **测试基础对话**
   - 发送简单问候："你好"
   - 应该正常返回

4. **测试工具调用**
   - 发送："帮我获取商品列表"
   - 应该调用 `get_products` 工具

5. **验证 Web Search 禁用**
   - 查看终端日志
   - 不应该出现 web_search 相关错误

### 预期行为

✅ **正常情况**
- 基础对话工作正常
- 自定义工具（get_products, generate_site, chart, weather）正常
- 没有 web_search 或 reasoningSummary 错误
- 流式响应正常

❌ **异常情况**
- 模型名称错误：检查端点支持的模型
- API Key 错误：验证 Key 是否正确
- 网络错误：检查端点可访问性

## 常见错误

### 错误 1: Resource not found (404)

```
ERROR litellm.APIError: AzureException APIError - 
{"error":{"code":"404","message": "Resource not found"}}
```

**原因**: 模型名称在自定义端点中不存在

**解决**: 
1. 查看端点支持的模型列表
2. 修改 `shared/utils/models.ts` 使用端点支持的模型名

### 错误 2: reasoningSummary not supported

```
AI SDK Warning: The feature "reasoningSummary" is not supported
```

**原因**: 使用了非推理模型

**解决**: 已自动修复，无需操作

### 错误 3: Web Search 失败

```
ERROR: web_search tool failed
```

**原因**: 自定义端点不支持内置 web_search

**解决**: 已自动禁用，无需操作

## 切换回官方端点

如果你想使用官方 API 并启用所有功能：

1. **修改 .env**
   ```bash
   # 移除或注释掉自定义端点
   # OPENAI_BASE_URL=https://llm.dhcoder.net
   # ANTHROPIC_BASE_URL=https://llm.dhcoder.net
   
   # 使用官方 API Key
   OPENAI_API_KEY=sk-proj-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

2. **重启服务器**
   ```bash
   pnpm dev
   ```

3. **验证功能**
   - Web Search 应该自动启用
   - 所有工具正常工作
