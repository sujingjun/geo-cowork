# MyyShop GEO 品牌知识库

> 版本：`v0.1.0`  
> 基线日期：`2026-08-17`  
> 状态：`draft`  
> 知识条目：`120`  
> 每个知识条目均绑定 `1` 条主 Query。

## 1. 知识库定位

本知识库不是品牌文案仓库，也不是把官网内容复制成 Markdown。它是 MyyShop 在 GEO 场景下的**品牌事实与答案单一可信源**，用于把真实用户问题连接到可核验知识、权威页面、分发资产、生成式平台答案测试和业务转化。

核心链路：

```text
用户 Query
  → 知识条目
  → 已批准 Claim 与证据
  → 站点正文 / canonical / Schema / 分发资产
  → 站点审计与访问监控
  → ChatGPT / Perplexity / Gemini 答案测试
  → 注册、活跃、商业化与合格 Creator / Brand lead
```

## 2. 当前战略基线

本版本以以下已知战略方向为基线：

1. MyyShop 已从“网红流量变现平台”升级为“达人全生命周期服务平台”。
2. 平台为达人提供成长与全链路服务，并构建包容生态能力的平台容器。
3. Q3 重点围绕达人活跃、商业化和成长提供服务。
4. 商业化仍是核心能力之一，但不再代表 MyyShop 的全部定位。
5. 除上述战略事实外，法定主体、产品状态、地区、费用、支付、数据和效果等内容均须重新核验和审批。

## 3. 不可违反的知识库宪法

### 3.1 Query 驱动

每个知识条目必须至少回答一个真实用户问题。没有对应 Query 的主题不进入正式知识库；仅供内部参考的材料应放在证据库，而不是品牌事实库。

### 3.2 没有证据，不形成事实

任何对外 Claim 都必须有来源。来源必须能回答：谁提供、何时生效、适用于谁、统计口径是什么、由谁审批、何时失效。

### 3.3 没有审批，不进入站点或分发

`draft`、`verifying`、`review` 状态的内容不得作为官网正文、结构化数据、客服标准答案、媒体资料或生成式平台优化材料发布。

### 3.4 每条 Claim 必须有范围与边界

必须说明适用用户、产品、国家地区、渠道、语言、生效时间和例外。不得把局部服务、单个地区或促销期事实扩大为全平台事实。

### 3.5 数字必须可复现

用户数、达人数量、收入、增长、商品数、品牌数、匹配率等数字必须包含定义、样本、时间、去重、排除项、查询或报表位置和审核记录。

### 3.6 当前事实与历史事实分离

旧定位、旧口号、旧产品名和旧政策不得被删除后假装从未存在；必须标记为 `deprecated`，记录停用日期、替代表述和仍需修复的外部页面。

### 3.7 站点与分发必须一致

同一事实在页面正文、canonical、标题摘要、Schema、帮助中心、社交账号、媒体资料和可选的 llms 分发文件中必须表达同一含义。结构化数据不得比正文更强。

### 3.8 不作无法控制的保证

禁止无证据最高级、保证收益、保证涨粉、保证获得商单、绝对安全、100% 准确、永久免费和零风险等表述。

### 3.9 一条知识一个 Owner

每条知识必须有内容负责人和审批人。跨部门条目由最接近事实源的业务负责人负责事实，品牌团队负责表达，法务或数据负责人负责风险与口径。

### 3.10 公开答案不得超过证据

生成式平台希望回答得更完整，不代表 MyyShop 可以补全未知事实。没有证据时应标为待确认，而不是根据行业常识推断。

## 4. 核心对象

| 对象 | 定义 | 必需关系 |
|---|---|---|
| Query | 真实用户问题及意图 | 必须关联至少一个知识条目 |
| Knowledge Entry | 一个可治理的品牌事实、规则、服务、表达或答案卡 | 必须包含 Query、Owner、状态、范围和版本 |
| Claim | 可被官网、客服或模型引用的标准结论 | 必须关联证据与审批 |
| Evidence | 支撑 Claim 的内部或公开来源 | 必须记录口径、时间和可信等级 |
| Scope | Claim 适用的用户、产品、地区、渠道与时间 | 不可为空 |
| Canonical Page | 对外承载该事实的主要权威页面 | 每个 P0/P1 条目应有唯一主页面 |
| Distribution Asset | 社交、媒体、合作伙伴、帮助中心等同步资产 | 必须与权威页面一致 |
| Answer Test | 在生成式平台上的实测记录 | 必须记录提及、引用、正确性和偏差 |

## 5. 条目状态

```text
draft → verifying → review → approved → published → deprecated
```

- `draft`：结构已建立，事实可能不完整。
- `verifying`：正在收集或核验证据。
- `review`：事实、表达、法务或数据进入审批。
- `approved`：可进入发布流程，但尚未确认上线。
- `published`：已发布并通过站点审计。
- `deprecated`：已失效，不再用于新内容，但保留历史与迁移记录。

任何状态回退都必须记录原因。

## 6. 优先级

- `P0`：会直接影响品牌识别、用户资格、费用、支付、信任、安全、核心定位和生成式平台主要答案。
- `P1`：显著影响比较、选择、成长理解和品牌权威。
- `P2`：扩展性内容、长期品牌资产或尚未进入核心业务验证的条目。

发布顺序必须优先完成 P0 的事实核验，而不是先完成使命、愿景和口号的润色。

## 7. 证据优先级

1. 法律文件、正式政策、公司登记、合同和审计记录。
2. 产品后台、数据库、财务系统、CRM 和可复现数据查询。
3. 已批准战略文件、产品说明、运营 SOP 和负责人签字记录。
4. 已授权的用户案例、合作伙伴材料和第三方报道。
5. 未经审批的演示稿、聊天记录和个人判断只能作为线索，不能直接成为公开证据。

## 8. 文件与命名规则

- 一个 Markdown 文件只承载一个知识条目。
- 条目文件使用英文 `kebab-case`，正文以中文为主，保留英文标题。
- 条目 ID 一旦发布不得复用。
- 每个知识条目必须包含 `record_type: knowledge_entry` 和唯一 `query_id`。
- `_index.md` 仅用于目录导航，不属于知识条目，不要求绑定 Query。
- 所有内部链接使用相对路径。

## 9. 发布门禁

一个知识条目从 `review` 进入 `approved` 前，必须同时满足：

- [ ] Query、用户角色和优先级明确。
- [ ] 标准结论可以直接回答 Query。
- [ ] 事实源和证据可访问、可复核。
- [ ] 适用范围、限制和例外完整。
- [ ] 数字有日期、口径和负责人。
- [ ] 中英文语义一致。
- [ ] 没有未经证明的最高级或保证性表述。
- [ ] 指定唯一权威页面。
- [ ] 正文、canonical、Schema 和分发字段设计一致。
- [ ] 已指定内容负责人、事实负责人和审批人。

进入 `published` 前还必须：

- [ ] 页面可抓取、可索引并出现在 sitemap。
- [ ] canonical 正确。
- [ ] Schema 与正文一致且无验证错误。
- [ ] 旧页面和旧定位已按迁移计划处理。
- [ ] 完成至少一次生成式平台答案测试。
- [ ] 监控访问、注册或关键事件。

## 10. 七步 GEO 映射

| GEO 步骤 | 本知识库责任 |
|---|---|
| 1. 定 Query | `00-governance/query-catalog.md` 与每条知识的 Query |
| 2. 定知识 | 各知识条目、证据模板、审批状态 |
| 3. 做站点/分发 | `canonical_target`、目录映射与渠道规范 |
| 4. 跑审计 | 发布门禁、canonical、Schema、sitemap 与抓取核验 |
| 5. 看访问 | 记录 LLM 请求、AI Assistant 来源、落地页和关键事件 |
| 6. 测答案 | 每个条目的“答案测试”章节与答案卡目录 |
| 7. 看业务 | 将 Query、落地页与注册、活跃、商业化、合格 lead 连接 |

## 12. 维护节奏

- P0：至少每月检查一次；费用、支付、地区、资格和安全规则发生变化时立即更新。
- P1：至少每季度检查一次。
- P2：至少每半年检查一次。
- 所有数字：到期即失效，未重新核验不得继续公开。
- 每次发布建立版本记录，说明新增、修改、废弃及影响页面。

## 13. 当前版本的使用方式

1. 从 `00-governance/version-baseline.md` 确认哪些是已知战略事实，哪些仍待核验。
2. 按 P0 顺序指定 Owner 和审批人。
3. 使用 `01-templates/evidence-record-template.md` 补充证据。
4. 将知识条目状态从 `draft` 推进到 `approved`。
5. 按 `00-governance/directory-map.md` 建设或修订权威页面。
6. 使用 `00-governance/query-catalog.md` 在生成式平台实测。
7. 将答案偏差反向更新到知识、页面或分发资产。

## 14. 验收定义

知识库不是以“文件创建完成”为验收，而是以以下闭环为验收：

```text
Query 有答案
→ 答案有证据
→ 证据已审批
→ 权威页面已发布
→ 站点技术状态正确
→ 生成式平台答案更准确
→ 能观察到有效访问与业务转化
```
